# Диагностика

## Контейнер не запущен

```bash
docker compose config -q
docker compose ps
docker compose logs --tail=100 <service>
```

Замените `<service>` на `qbittorrent`, `radarr`, `sonarr`, `prowlarr`, `jellyfin`, `jellyseerr` или `flaresolverr`. Если порт занят, найдите конфликтующий процесс и освободите порт либо осознанно измените проброс.

## Нет доступа к файлам

Проверьте `id -u`, `id -g`, значения `.env`, права на `config/` и `data/`, а также `ls -Zd config data`. Все пишущие сервисы должны иметь доступ к `/data`. На Fedora проверьте `getenforce` и сообщения SELinux. В Compose конфигурации имеют `:Z`, общие данные — `:z`. Не отключайте SELinux как первый способ исправления; исправьте путь, владельца и метки. После смены UID/GID может понадобиться скорректировать владельца файлов своего проекта.

## Сервисы не соединяются

Внутри Compose используйте имена `qbittorrent`, `radarr`, `sonarr`, `prowlarr`, `jellyfin`, `jellyseerr` и соответствующие внутренние порты. `localhost` внутри контейнера — сам контейнер. На браузере Fedora используйте `localhost:<порт>`, на ТВ — LAN-IP хоста. API-ключи копируйте только в формы сервисов. Для Jellyfin на ТВ проверьте firewall для `8096/tcp`.

## Импорт не работает

Сверьте категории `movies`/`tv`, путь qBittorrent `/data/torrents/...`, корневой путь Radarr/Sonarr `/data/media/...` и права записи. Все три контейнера должны видеть один и тот же путь `/data`. Если данные лежат на разных файловых системах, жёсткие ссылки работать не будут. Проверяйте журнал конкретного сервиса и очередь загрузок.

## Нет нужного языка

Проверьте Custom Formats, баллы в активном профиле качества и название релиза. Затем проверьте аудиодорожки фактического файла в Jellyfin. Маркеры названия не гарантируют язык дорожки.
